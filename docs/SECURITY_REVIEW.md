# セキュリティレビュー

更新日: 2026-09-21

## 対象フロー

1. 利用者がエリア、人数、予算、希望条件を入力
2. サーバーがホットペッパーグルメWebサービスから実店舗を取得
3. 公開店舗情報と匿名化された条件だけをOrcaRouterへ送信
4. 専門担当3つが並列分析し、統括担当が候補・確認事項・次の行動を統合
5. 幹事がグループを作り、参加者が予約内容・チャット・自分の回答を確認

## 確認結果

| 対象 | 対策 | 検証 |
|---|---|---|
| APIキー | サーバー環境変数のみ。`NEXT_PUBLIC_`を使用しない | レスポンスへOrcaRouterキーが含まれないことを統合試験 |
| CSRF | JSON POSTを同一Originに限定 | 外部Originを403で拒否することを統合試験 |
| 入力DoS | リクエスト本文16KiB、文字数、人数、予算、候補数を制限 | 不正な予算と入力を400で拒否 |
| コスト濫用 | 送信元ごとに1時間10回、全体に日次上限 | DBのアトミックなカウンターを使用 |
| SSRF・キー誤送信 | Hosted版と明示的に許可したホストだけへ接続 | 未許可ホストを設定段階で拒否 |
| プロンプトインジェクション | 外部店舗データを非信頼データと明示。モデル出力の店舗IDを入力候補で許可リスト検証 | 攻撃文字列と架空IDを含む応答を統合試験 |
| AI出力改ざん | 文字数、配列数、スコア範囲、店舗IDをサーバーで再検証 | 不正IDを除外し既知候補へフォールバック |
| AI障害 | 店舗検索と候補分析を分離 | AIのJSONエラーやHTTPエラーで店舗候補を削除しない |
| 保存データ | 予約内容とアレルギー情報をAES-256-GCMで暗号化 | DBの値が`v1:`暗号形式で平文を含まないことを統合試験 |
| セッション | 32バイト乱数をHttpOnly / SameSite Strict Cookieへ保存し、DBにはSHA-256ハッシュのみ保存 | 未参加者・退出者・別グループのアクセス拒否を統合試験 |
| 権限 | 予約編集、共有、招待再発行、参加者削除を幹事だけに限定 | 参加者の編集・共有を403で拒否 |
| アレルギー情報 | 本人と幹事だけに返却。OrcaRouterへ品目を送らない | 他参加者のレスポンスに詳細が存在しないことを統合試験 |

## 残存リスクと運用条件

- OrcaRouterは1ワークフローあたり最大4回呼び出すため、単発呼び出しより料金と待ち時間が増えます。利用量アラートと`ENCOPA_AGENT_DAILY_LIMIT`を設定してください。
- Hosted版OrcaRouterの本番疎通は実キーを設定したVercel Previewで確認する必要があります。自動試験ではOpenAI互換モックを使用しています。
- 既存の平文レコードは読み取り互換を維持しています。更新時から暗号化されるため、既存環境では別途一括再暗号化を計画してください。
- `ENCOPA_DATA_KEY`を失うと暗号化済みデータを復号できません。Vercel環境変数と組織の秘密管理基盤でバックアップし、通常のキーと同じ手順で単純交換しないでください。
- ホットペッパー、OrcaRouter、Tursoの障害は完全には排除できません。店舗検索と候補分析は分離しており、分析障害時も取得済み候補の比較を継続できます。
- ブラウザからの実画面確認は現在のクラウドブラウザがローカルアドレスを拒否したため、ソース・本番ビルド・API統合試験で代替しました。Vercel PreviewでスマートフォンとPCの表示を最終確認してください。
